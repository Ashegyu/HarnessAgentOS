# HarnessAgentOS Patterns

> Extracted from the live source tree, the
> [docs/](../../../../docs/) reference set, and the test suite (167+ tests, all
> `*.test.mjs`). Updated 2026-05-11 after Phase 8 Agent CLI integration.

## Stack snapshot

- Electron 31 + React 18 + Vite 5 (electron-vite). Renderer loads built
  files only — there is no localhost dev server.
- SQLite via `better-sqlite3` with `PRAGMA journal_mode=WAL`. SQLite is
  the single canonical state.
- TypeScript ESM (`"type": "module"`, `moduleResolution=Bundler`).
- npm workspaces: `apps/desktop` + `packages/{core,storage,runners,quality,skillify-adapter,learner,orchestration,agent}`.

## Layered architecture (load-bearing)

Strict, enforced by `docs/engineering/conventions.md`:

| Layer | Allowed | Forbidden |
|--|--|--|
| Renderer (`apps/desktop/src`) | UI state, presentation, `window.harness` calls | filesystem, DB, child_process, raw `ipcRenderer`, fetch |
| Preload (`apps/desktop/electron/preload.ts`) | typed `contextBridge` API + minimal shape guards | wildcard channel forwarding, exposing raw `ipcRenderer` |
| Main / IPC (`apps/desktop/electron/ipc/*-ipc.ts`) | thin handlers — validate input, call services, normalise errors | business logic |
| Service (`packages/*/src/*-service.ts`) | domain logic, policy, validation | direct SQL, OS calls inside core |
| Repository (`packages/storage/src/repositories/*-repository.ts`) | SQL only, snake_case row mappers | policy decisions |

When adding a method, all five layers usually change together. The
single source of truth for IPC channel strings is
[packages/core/src/ipc-channels.ts](../../../../packages/core/src/ipc-channels.ts);
namespace assertions in
[ipc-channels.test.mjs](../../../../packages/core/src/ipc-channels.test.mjs)
catch drift.

## File naming

| Kind | Pattern | Example |
|--|--|--|
| React component | `PascalCase.tsx` | `QualityPanel.tsx`, `AgentPanel.tsx` |
| Service / policy / repository | `kebab-case.ts` | `conversation-service.ts`, `agent-planning-service.ts` |
| IPC handler | `{domain}-ipc.ts` | `quality-ipc.ts`, `agent-ipc.ts` |
| Tests | `*.test.mjs` (Node test runner via `tsx`) | `agent-output-parser.test.mjs` |
| Domain types | `packages/core/src/types/*.ts` | `agent-invocation.ts`, `agent-plan-output.ts` |

There are zero `.test.ts`/`.test.tsx` files — keep new tests on
`*.test.mjs`. Run with the workspace `test` scripts (root `npm test`
fans out via `--workspaces --if-present`).

## Domain ID prefixes

`thr_/tsk_/stp_/ckp_/apv_/art_/qg_/cap_/lrn_/agi_` — generated by
[packages/storage/src/id.ts](../../../../packages/storage/src/id.ts) (`newId(prefix)`).
When adding a new domain object, register a prefix here and use
`newId("xyz")` rather than ad-hoc UUIDs.

- `agi_` is the prefix for `AgentInvocation` rows (Phase 8).

## Domain flow (canonical sequence)

```
Thread → TaskRun → Step → Checkpoint → Approval → Artifact
           │                                     ↓
           └─ AgentInvocation                QualityGateResult → LearningTrace
```

`AgentInvocation` sits between TaskRun and the Approval/Artifact that
`AgentPlanningService.generatePlan` produces. Its status transitions:

- `queued` → `running` (when CLI starts)
- `running` → `succeeded` (plan parsed, Approval rows created)
- `running` → `failed` (CLI error or parse error)
- `queued`/`running` → `cancelled` (explicit cancel or retry supersedes)

TaskRun status transitions are owned by services, never by the renderer:

- `drafting` → `waiting_for_approval` (`ConversationService.createTask`)
- `running` → `quality_failed` / `ready_for_review` (`TaskRunCompletionService.applyQualityGateResult`)
- `ready_for_review` → `done` (`TaskRunCompletionService.markDone` — fires `onTaskRunDone` hook to stamp LearningTrace **before** flipping status)
- any non-terminal → `paused` / `cancelled` (`ConversationService.pauseTask` / `cancelTask`)

`done` and `cancelled` are terminal.

## Service patterns

### Dependency-inject storage gateways

Services in `@harness/core` never import `@harness/storage`. They depend
on a narrow gateway interface that lists only the methods they actually
need. Examples:

- [TaskRunCompletionGateway](../../../../packages/core/src/task-run/completion-gateway.ts)
- [ConversationStateGateway](../../../../packages/core/src/conversation/conversation-gateway.ts)

This keeps `core` storage-agnostic and lets tests substitute fakes.

### Optional completion hooks

When one service needs to trigger work in another package without
creating an import cycle, use an optional async hook on the service
deps. Example: `TaskRunCompletionService.onTaskRunDone?` is bound in
`main.ts` to `traceRecorder.recordOutcome`. The hook fires **before**
the destructive state change so failures are atomic.

## Repository patterns

- One file per table: `{domain}-repository.ts`.
- snake_case columns, camelCase domain objects. Mapping lives in
  [row-mappers.ts](../../../../packages/storage/src/repositories/row-mappers.ts).
- JSON columns get a `_json` suffix.
- Migrations are idempotent and applied at `openDb()` time.
- Repositories never decide policy — that's the service's job.

## IPC pattern

```ts
// 1. Channel string — single source in core/src/ipc-channels.ts
IPC_CHANNELS.<namespace>.<verb> = "<namespace>:<verb>";

// 2. Renderer-facing type — HarnessDesktopApi in core/src/api.ts

// 3. Handler — apps/desktop/electron/ipc/<namespace>-ipc.ts
ipcMain.handle(IPC_CHANNELS.foo.bar, async (_e, input: unknown) => {
  if (!isObject(input)) return err(harnessError(STATE_INVALID_INPUT, "..."));
  // narrow + validate + delegate to service
  try {
    const result = await service.bar(payload);
    events.taskRunChanged(result.taskRunId); // if state-changing
    return ok(result);
  } catch (e) { return mapServiceError(e); }
});

// 4. Preload — invokeUnwrapped<T>(channel, input)

// 5. Docs/contracts/ipc-contracts.md is the human contract.
```

State-changing IPC handlers must broadcast `events:taskRunChanged` so
the renderer (`WorkbenchShell`) refetches without polling.

## Agent package (`@harness/agent`) — Phase 8

The `packages/agent/` package owns everything related to CLI-based
agent invocations. It is the **only** package that may spawn child
processes to call `claude`/`codex` CLIs.

### Key classes

| Class | Role |
|--|--|
| `AgentPlanningService` | Orchestrates a full plan-generation round-trip (prompt → CLI → parse → persist → approve) |
| `AgentInvocationQueue` | Serializes concurrent invocations per-provider; reports `queueDepth` to `RuntimeStatusBar` |
| `DefaultModelCliAdapter` | Wraps `spawn()` for the real CLI; emits `AgentStreamEvent` chunks |
| `FakeModelCliAdapter` | In-process test double — injects canned stdout |
| `AgentOutputParser` | Validates CLI stdout as `AgentPlanOutput` JSON |
| `AgentPromptBuilder` | Assembles the system+user prompt from `TaskRun`, `Thread`, and optional `instruction` |

### Provider detection

`providerDetection.ts` checks `claude --version` and `codex --version`
at startup. Results are cached in `main.ts` as `providerStatusCache` and
refreshed on `agent:checkProviders`. The cache is passed as
`getProviderStatus()` to `AgentPlanningService` to gate calls without
re-probing on every request.

### Stream event push

During `generatePlan`, the planning service emits `AgentStreamEvent`
chunks via `deps.emitStreamEvent`. In `main.ts` this is wired to
`eventBus.agentStreamEvent(event)`, which broadcasts
`events:agentStreamEvent` to all renderer windows **after
secret-redaction via `@harness/learner`'s `redactSecrets`**.

Renderer subscribes in `AgentStreamView.tsx`:
```ts
window.harness.events.onAgentStreamEvent(handler);
```

Filter by `event.invocationId` — multiple invocations may overlap.

### AgentPlanningError

`AgentPlanningError(code, message)` is the typed error thrown by
`AgentPlanningService`. The IPC layer catches it and maps to
`harnessError(e.code, e.message)`. Never throw plain `Error` from this
service.

### Template fallback

`agent:useTemplateFallback` guards against concurrent agent invocations:
it rejects with `AGENT_INVOCATION_BUSY` if any invocation for the same
`taskRunId` is still `queued` or `running`. The user must cancel first.

## Error handling

- User-facing errors are normalised to `HarnessError` (`code`, `message`,
  optional `details`) — see [packages/core/src/error.ts](../../../../packages/core/src/error.ts).
- IPC always returns `HarnessResult<T>` (`{ ok: true, value }` or
  `{ ok: false, error }`). Preload unwraps so renderer sees `Promise<T>`.
- Service errors are typed (`ConversationServiceError`,
  `TaskRunCompletionError`, `RunnerError`, `OrchestrationError`,
  `AgentPlanningError`) with a string `code` field that the IPC layer
  maps to `HarnessError.code`.
- Policy denials are not failures — they're explicit `blocked`/`rejected`
  decisions that get persisted (Approval row, Step status, artifact).

### Agent-specific error codes (new in Phase 8)

```ts
AGENT_PROVIDER_UNAVAILABLE  // CLI not found or probe failed
AGENT_TASK_RUN_NOT_FOUND    // taskRunId doesn't exist
AGENT_INVOCATION_NOT_FOUND  // invocationId doesn't exist
AGENT_INVOCATION_BUSY       // queued/running invocation blocks fallback
AGENT_MODE_MISMATCH         // provider returned unexpected output mode
AGENT_PROPOSED_ACTION_INVALID // plan action failed validation
```

### Deprecated error code aliases (do not use in new code)

Phase 8 renamed several constants to match `docs/contracts/ipc-contracts.md`.
The old names are kept for one release as `@deprecated` aliases:

| Old (deprecated) | New (canonical) |
|--|--|
| `CAPABILITY_UNTRUSTED_SCRIPT` | `CAPABILITY_UNTRUSTED_SKILL` |
| `LEARNER_DECISION_INVALID` | `LEARNER_INVALID_DECISION` |
| `ORCH_TASK_NOT_FOUND` | `ORCHESTRATION_TASK_NOT_FOUND` |
| `ORCH_INVALID_PLAN` | `ORCHESTRATION_INVALID_PLAN` |
| `ORCH_APPROVAL_NOT_APPROVED` | `ORCHESTRATION_APPROVAL_REQUIRED` |

Always import the canonical long-form constant. When editing existing
code that uses the deprecated aliases, upgrade them in the same PR.

## Approval / runner policy

- **Every** side effect goes through an `Approval` row. The runner gates
  itself behind `approval.status === "approved"` and a normalised
  `proposedAction`.
- Schema validation runs at the IPC boundary
  ([proposed-action-validator.ts](../../../../packages/core/src/conversation/proposed-action-validator.ts)) so service/runner trust the payload.
- High-risk action types (`dependency_install`, `git_commit`, `network`,
  `skill_script`, `orchestration_plan`) are blocked at the runner gate
  in MVP.
- Shell commands matching `isTestCommand` get classified as a `test`
  step (not `shell`) so the timeline shows test pass/fail at the right
  granularity.
- `targetDir` is enforced server-side — the renderer cannot override
  `cwd`.

## Quality gate / done policy

`TaskRunCompletionService.markDone` is the only path to `done`:

| `gate.status` | `markDone` allowed |
|--|--|
| `passed` | yes |
| `warning` | only if a `quality_report` artifact exists whose URI ends with `/<gate.id>` (the known-risk approval — `quality.approveKnownRisks` writes `harness:quality/<taskRunId>/<gate.id>`) |
| `failed` / `not_run` | no — `QUALITY_DONE_BLOCKED` |

## Testing patterns

- Node test runner: `node --test --import tsx --enable-source-maps`.
- Files: `*.test.mjs` next to source, importing the `.ts` siblings.
- Repository tests open a temp SQLite file in `mkdtempSync`, exercise
  the table, then `closeDb` + `rmSync` in `finally`.
- Service tests use the same temp-DB pattern through `LocalStateService`.
- Runner tests work in a temp `targetDir` — they never touch the
  developer's filesystem.
- Agent tests use `FakeModelCliAdapter` — never invoke real `claude`/
  `codex` binaries. Inject `{ defaults: { timeoutMs: 500, stallTimeoutMs: 200 } }`
  to `AgentPlanningService` so tests don't hang.
- Predicate matching for `assert.rejects` uses `(e) => e.code === "X"`
  rather than regex on `.toString()` (Error.toString doesn't include
  `code`).
- `npm run verify` = `check + test + build`. E2E (Playwright + Electron)
  is `npm --workspace=@harness/desktop run e2e` and runs against the
  built bundle in an isolated `userData` directory.

## Renderer event push

`apps/desktop/electron/event-bus.ts` broadcasts two push channels:

| Channel | Trigger |
|--|--|
| `events:taskRunChanged` | Any IPC call that mutates a `TaskRun` row |
| `events:agentStreamEvent` | Each `AgentStreamEvent` chunk during `generatePlan` |

[WorkbenchShell.tsx](../../../../apps/desktop/src/screens/workbench/WorkbenchShell.tsx)
subscribes to `events:taskRunChanged`. `AgentStreamView.tsx` subscribes
to `events:agentStreamEvent`. Renderer never polls.

## Documentation update order

When you change behaviour:

1. Update [docs/contracts/ipc-contracts.md](../../../../docs/contracts/ipc-contracts.md) **first** if IPC changes.
2. Update [docs/architecture/architecture-decisions.md](../../../../docs/architecture/architecture-decisions.md) for non-trivial direction changes (ADR style).
3. Update [docs/product/mvp-user-flows.md](../../../../docs/product/mvp-user-flows.md) for user-flow changes.
4. Update [docs/testing/acceptance-checklist.md](../../../../docs/testing/acceptance-checklist.md) for acceptance criteria changes.
5. Update [docs/CODEMAPS/](../../../../docs/CODEMAPS/) for new structural surfaces (where things live).
6. Then change the code and tests.

## Forbidden patterns (from conventions.md)

- ❌ Adding an Express/localhost/WebSocket server.
- ❌ `nodeIntegration: true` or any renderer-side Node/FS access.
- ❌ Using JSON files as canonical state (SQLite only).
- ❌ Side effects without a corresponding approved `Approval` row.
- ❌ Modifying the legacy `ClaudeAgentSystem` repo at `C:\Users\FORYOUCOM\Desktop\Code\ClaudeAgentSystem` (read-only reference).
- ❌ Auto-applying Skillify/Learner suggestions — they propose, the user approves.
- ❌ `console.log` in production code (use artifacts/log artifacts).
- ❌ Calling real `claude`/`codex` CLIs in unit tests — use `FakeModelCliAdapter`.
- ❌ Using deprecated `ORCH_*`, `CAPABILITY_UNTRUSTED_SCRIPT`, `LEARNER_DECISION_INVALID` constants in new code.

## Adding a new IPC method — checklist

1. `packages/core/src/ipc-channels.ts` — add `namespace.verb`.
2. `packages/core/src/ipc-channels.test.mjs` — extend the namespace assertion.
3. `packages/core/src/api.ts` — add the typed method to `HarnessDesktopApi`.
4. Service implementation (with input validation + typed errors).
5. `apps/desktop/electron/ipc/<namespace>-ipc.ts` — handler registers, validates, delegates, broadcasts on success.
6. `apps/desktop/electron/preload.ts` — wire `invokeUnwrapped`.
7. UI consumer (component + state action).
8. Test (unit for service, IPC namespace assertion).
9. `docs/contracts/ipc-contracts.md` — describe the new method, error codes, transitions.

Run `npm run verify` (check + test + build) before declaring done.

## Adding a new agent provider — checklist

1. Extend `AgentProvider` type in `packages/core/src/types/agent-invocation.ts`.
2. Add detection logic in `packages/agent/src/provider-detection.ts`.
3. Add model-string → provider mapping in `providerForModel`.
4. Add prompt-builder branch in `agent-prompt-builder.ts` if the prompt
   format differs.
5. Add output-parser branch in `agent-output-parser.ts` if the output
   schema differs.
6. Add test coverage using `FakeModelCliAdapter` with the provider's
   canned output.
7. Update `AgentProviderStatusMap` in `packages/core/src/types/agent-invocation.ts`.
8. Update `docs/contracts/ipc-contracts.md` provider probe section.
