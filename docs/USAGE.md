## 1. 앱 개요

HarnessAgentOS는 AI 에이전트(Claude Code CLI, OpenAI Codex)를 통해 소프트웨어 작업을 관리하는 Electron 데스크탑 앱입니다. 핵심 개념은 다음 세 가지입니다.

| 개념 | 설명 |
|------|------|
| **Thread** | 프로젝트 단위의 작업 묶음. 하나의 Thread 안에 여러 TaskRun이 쌓입니다. |
| **TaskRun** | Thread 내의 단일 작업 실행 단위. 사용자 요청 하나 = TaskRun 하나. |
| **AgentInvocation** | Agent 모드에서 TaskRun이 CLI를 호출할 때 생성되는 실행 기록. |

## 2. 화면 레이아웃

```
┌─────────────────────────────────────────────────────────────────┐
│  Thread Sidebar (240px) │  Workbench (1fr)  │  Right Panel (360px)│
│                         │                   │                     │
│  [ + 새 작업 ]          │  [스레드 제목]    │  [Plan][Agent]…     │
│  ─────────────          │  ──────────────── │  ─────────────────  │
│  스레드 목록             │  채팅 트랜스크립트 │  Plan / Approval    │
│                         │                   │  Agent 스트림       │
│                         │                   │  Timeline           │
│                         │  [ 입력창 ]       │  Artifacts          │
│  ─────────────          │                   │  Quality            │
│  [ ⚙ Agents ]          │                   │  Capabilities       │
├─────────────────────────────────────────────────────────────────┤
│  Runtime 상태바  ·  v버전  ·  플랫폼  ·  데이터 경로  ·  ⚙설정  │
└─────────────────────────────────────────────────────────────────┘
```

- **Thread Sidebar**: 좌측 패널. 스레드 목록 + Agents 버튼.
- **Conversation Workbench**: 중앙 패널. 선택된 Thread의 대화 흐름과 입력창.
- **Right Panel**: 우측 패널. 선택된 TaskRun의 상세 정보(Plan, Approvals, Agent 로그 등).
- **Runtime Status Bar**: 최하단 고정 바. 런타임 상태, 버전, ⚙ 설정 버튼.

## 3. 스레드 관리

### 3-1. 새 스레드 만들기

1. 사이드바 상단의 **+ 새 작업** 버튼 클릭.
2. 폼이 펼쳐집니다:
   - **제목**: 작업을 구분하는 이름. 예: `결제 모듈 리팩토링`
   - **대상 폴더 (선택)**: 이 스레드에서 기본으로 쓸 프로젝트 디렉터리. **찾아보기…** 버튼으로 OS 파일 탐색기를 열 수 있습니다.
3. **생성** 버튼 또는 Enter 키로 제출.

> **예제**
> - 제목: `API 서버 성능 개선`
> - 대상 폴더: `C:\Users\me\Code\backend-api`
>
> → 생성 후 해당 스레드가 자동 선택되고 Workbench가 비어 있는 상태로 표시됩니다.

### 3-2. 스레드 선택

목록에서 스레드를 클릭하면 Workbench에 해당 Thread의 대화 내역이 로드됩니다.

각 항목에는:
- **제목** — 스레드 이름
- **최종 수정 시각** — 마지막으로 업데이트된 시간
- **대상 폴더** (지정된 경우) — 프로젝트 경로

### 3-3. 스레드 삭제

스레드 항목 오른쪽의 **×** 버튼 클릭 → 확인 대화상자 → 확인 시 스레드와 안에 있는 **모든 TaskRun이 함께 삭제**됩니다.

## 4. 작업(TaskRun) 생성

스레드를 선택하면 Workbench 하단에 **입력창**이 나타납니다.

입력창 구조:

```
대상 폴더: [표시된 경로]          [변경]
──────────────────────────────────────
[Template]  [Agent]               ← 모드 선택
──────────────────────────────────────
[                              ]  ← 요청 텍스트 (3행)
──────────────────────────────────────
(힌트 메시지)                [전송]
```

- **Enter** 키로 전송, **Shift+Enter**로 줄바꿈.
- 대상 폴더가 설정되어야 전송 버튼이 활성화됩니다.

## 5. Template 모드

**선택 방법**: 입력창 모드 버튼에서 `Template` 선택 (기본값).

Template 모드는 미리 정의된 계획 템플릿을 이용해 ActionPlan을 만듭니다. Agent CLI가 없어도 동작합니다.

### 흐름

```
[사용자 입력] → TaskRun 생성(drafting) → 계획 생성 → ready_for_review
                                                         ↓
                                              [Right Panel에서 Approval 확인]
                                                         ↓
                                              [승인] → running → done
                                              [거부] → cancelled
```

### 예제

**요청**: `README.md 파일에 사용법 섹션을 추가해줘`

1. Template 모드 선택 후 입력, 전송.
2. Workbench에 요청 버블이 나타나고 `응답 준비 중…` 메시지가 표시됩니다.
3. 잠시 후 `응답 도착 — 우측 패널에서 확인` 상태로 바뀝니다.
4. 해당 TaskRun 버블 클릭 → 오른쪽 패널 Plan 탭에서 생성된 계획을 확인합니다.
5. Approvals 섹션에서 제안된 파일 수정을 승인하거나 거부합니다.

## 6. Agent 모드

**선택 방법**: 입력창 모드 버튼에서 `Agent` 선택. (Claude Code CLI 또는 Codex가 설치/설정된 경우에만 활성화됩니다.)

Agent 모드는 실제 CLI 프로세스를 실행해 코드를 분석하고, 계획을 수립하며, 파일 수정 등의 작업을 직접 제안합니다.

### 흐름

```
[사용자 입력] → TaskRun 생성 → agent.generatePlan() 호출
                                         ↓
                              AgentInvocation 생성(streaming)
                                         ↓
                              [Right Panel Agent 탭에서 실시간 로그 확인]
                                         ↓
                              계획 완성 → ApprovalRequest 생성
                                         ↓
                              [Right Panel Plan 탭 Approvals에서 승인/거부]
                                         ↓
                              승인 → runner.executeApproved() → 실행 완료
```

### 6-1. Agent 활성화 확인

하단 상태바에 **Claude** 또는 **Codex** 인디케이터가 초록색(●)으로 표시되어야 합니다. 빨간색(●)이면 해당 CLI가 설치되지 않았거나 PATH에 없는 것입니다.

### 6-2. Agent 모드로 작업 전송

> **예제**: `packages/api/src/auth.ts에서 JWT 만료 시간을 설정에서 읽도록 리팩토링해줘`

1. 스레드의 대상 폴더가 프로젝트 루트로 설정되어 있는지 확인.
2. 모드 버튼에서 `Agent` 선택.
3. 요청을 입력하고 전송.
4. 전송 직후 입력창에 `Agent 호출 중…` 메시지가 표시됩니다.
5. Workbench 버블 상태가 `Agent 응답 중…`으로 바뀝니다.
6. 오른쪽 패널 **Agent 탭**에서 실시간 스트리밍 로그를 볼 수 있습니다.

### 6-3. Agent 탭 상세

Right Panel의 **Agent** 탭에서 각 AgentInvocation의 상태와 로그를 확인합니다.

| 상태 | 표시 |
|------|------|
| `running` | 스피너 + 실시간 로그 |
| `done` | 완료 표시 + 전체 로그 |
| `failed` | 오류 메시지 + 재시도 버튼 |

**재시도**: 실패한 Invocation 옆의 **재시도** 버튼으로 같은 요청을 다시 실행합니다.

**취소**: 실행 중인 Invocation의 **취소** 버튼으로 중단합니다.

**Fallback**: Agent가 반복 실패할 경우 **Fallback 사용** 버튼이 나타납니다. 클릭하면 Template 모드로 전환되어 기본 계획 템플릿이 적용됩니다.

## 7. 오른쪽 패널 — TaskRun 상세

TaskRun 버블을 클릭하면 Right Panel에 7개 탭이 나타납니다.

### 7-1. Plan 탭

두 섹션으로 구성됩니다:

**Plan 섹션**: 에이전트가 생성한 작업 계획의 요약. 마크다운 형식으로 표시되며, 1200자를 초과하면 `더 보기`로 접힙니다.

**Approvals 섹션**: 에이전트가 요청한 작업 승인 목록.

각 Approval 항목에서:
- **승인** — 제안된 작업을 한 번 승인
- **이번 실행 전체 승인** — 같은 종류의 작업을 이번 TaskRun 전체에서 자동 승인
- **거부** — 거부 이유를 입력하면 에이전트에게 전달
- **재지시 (Redirect)** — 에이전트에게 새로운 방향 지시. 예: `파일을 수정하지 말고 먼저 테스트만 추가해줘`
- **Configure** — 제안된 액션의 세부 사항을 수동으로 수정한 뒤 실행
- **Execute** — 설정 완료 후 수동 실행

> **Approval 예제**
>
> 에이전트가 `src/config.ts` 파일 수정을 제안한 경우:
> 1. Plan 탭 → Approvals 섹션에서 해당 항목 확인.
> 2. 변경 내용(diff)을 검토.
> 3. **승인** 클릭 → 에이전트가 실제 파일 수정을 실행.

### 7-2. Agent 탭

AgentInvocation 목록과 각 실행의 스트리밍 로그. 위 [6-3](#6-3-agent-탭-상세) 참조.

### 7-3. Timeline 탭

TaskRun의 단계(Step)별 시간 흐름을 시각화합니다. 어떤 단계에서 시간이 걸렸는지 파악하는 데 유용합니다.

### 7-4. Artifacts 탭

TaskRun 실행 중 생성된 산출물(파일, 코드 스니펫 등) 목록. Plan 산출물은 별도의 Plan 탭에 표시되며, 이 탭에는 나머지 모든 Artifact가 표시됩니다.

### 7-5. Quality 탭

TaskRun의 품질 평가 결과. 에이전트가 생성한 결과물에 대해 평가 점수와 피드백을 확인하거나 수동으로 입력할 수 있습니다.

### 7-6. Capabilities 탭

두 섹션으로 구성됩니다:

**Capabilities 섹션**: 이 TaskRun이 사용하거나 요청한 기능 목록. 새로운 권한이 필요한 경우 여기서 Approval을 생성합니다.

**Learner 섹션**: 에이전트가 이번 실행을 통해 학습한 내용. 반복 작업에서 패턴을 파악하는 데 사용됩니다.

### 7-7. Orchestration 탭 (TaskRun 수준)

이 특정 TaskRun에 대한 오케스트레이션 상태를 보여줍니다. 전역 오케스트레이션 설정은 사이드바의 **⚙ Agents** 패널에서 합니다.

## 8. Agents & Orchestration 설정

사이드바 최하단의 **⚙ Agents** 버튼을 클릭하면 Agents 패널이 열립니다 (Workbench + Right Panel 영역을 대체).

### 8-1. Orchestration 활성화

패널 상단의 토글로 오케스트레이션을 켜거나 끕니다.

- **켜짐**: Agent 모드 실행 시 아래에서 설정한 모드와 Worker 프로필이 적용됩니다.
- **꺼짐**: 단일 기본 에이전트만 사용됩니다.

### 8-2. 실행 모드 선택

3가지 모드 카드 중 하나를 선택합니다:

| 모드 | 설명 | 언제 사용 |
|------|------|----------|
| **Single Worker** | 에이전트 하나가 모든 작업 처리 | 소규모 작업, 단순 수정 |
| **Planner + Worker** | 플래너가 계획하고 워커가 실행 | 여러 파일에 걸친 중간 규모 작업 |
| **Multi Worker** | 여러 에이전트가 병렬 처리 | 대규모 리팩토링, 멀티 모듈 작업 |

> **예제**: API 서버와 프론트엔드를 동시에 수정해야 하는 경우 → **Multi Worker** 선택.

### 8-3. Worker Agents 관리

**에이전트 추가** 버튼으로 Worker Profile을 생성합니다.

각 Worker 카드에서 설정 가능한 항목:

| 필드 | 설명 | 예시 |
|------|------|------|
| **이름** | 에이전트 구분 이름 | `백엔드 코더`, `리뷰어` |
| **역할** | 이 에이전트의 역할 | `Coder`, `Planner`, `Reviewer`, `Tester` |
| **Provider** | 사용할 CLI | `auto` (자동), `claude`, `codex` |
| **Model** | 특정 모델 지정 (선택) | `claude-sonnet-4-6`, 비워두면 기본값 사용 |

**삭제**: 카드 우측 상단의 **×** 버튼.

> **예제 구성 — Planner + Worker 모드**
>
> Worker 1:
> - 이름: `플래너`
> - 역할: `Planner`
> - Provider: `claude`
> - Model: `claude-opus-4-7`
>
> Worker 2:
> - 이름: `코드 작성`
> - 역할: `Coder`
> - Provider: `claude`
> - Model: (비워둠 — 기본값 사용)
>
> Worker 3:
> - 이름: `검토자`
> - 역할: `Reviewer`
> - Provider: `auto`
> - Model: (비워둠)

### 8-4. 기본 지시사항

플래너 에이전트에게 매 작업마다 전달되는 추가 지시입니다.

> **예제**
> ```
> 변경 전 반드시 테스트를 먼저 작성하세요.
> 코드 주석은 한국어로 작성하세요.
> 기존 타입 시스템을 깨뜨리지 마세요.
> ```

### 8-5. 저장 및 취소

- **저장**: 모든 설정을 영구 저장. 다음 Agent 실행부터 적용됩니다.
- **취소**: 변경사항 버리고 닫기. 또는 좌측 상단 **←** 버튼.

## 9. Settings 패널

하단 상태바 우측의 **⚙** 버튼을 클릭하면 Settings 모달이 열립니다.

### Agent 설정

| 설정 | 설명 | 기본값 |
|------|------|--------|
| **Provider** | 기본 CLI 선택 (`auto` / `claude` / `codex`) | `auto` |
| **Model** | 기본 모델 ID | 비어 있으면 Provider 기본값 사용 |
| **Timeout (ms)** | 전체 작업 최대 실행 시간 | 300,000 (5분) |
| **Stall Timeout (ms)** | 응답 없을 때 중단 기준 | 30,000 (30초) |
| **Context Depth** | 에이전트에게 전달할 이전 대화 깊이 | 3 |

> **권장 설정**
> - 빠른 편집 작업: Timeout 120,000ms, Context Depth 2
> - 복잡한 리팩토링: Timeout 600,000ms, Context Depth 5

## 10. 하단 상태바

```
● 런타임 준비됨  ·  v1.0.0  ·  win32  ·  C:\Users\me\AppData\...  ·  Claude ● Codex ●  ·  ⚙
```

| 항목 | 설명 |
|------|------|
| **● 런타임 준비됨** | 초록: 정상, 빨강: 오류, 회색: 확인 중 |
| **vX.Y.Z** | 앱 버전 |
| **win32 / darwin** | 플랫폼 |
| **데이터 경로** | 앱 데이터(DB, 설정)가 저장된 경로 (마우스 오버로 전체 경로 확인) |
| **Claude ● / Codex ●** | 각 CLI provider 가용 여부. 초록=설치됨, 빨강=미설치 |
| **⚙** | Settings 모달 열기 |

**Agent 버튼이 비활성화(회색)인 경우** → Claude 또는 Codex CLI가 PATH에 없습니다. 설치 후 앱을 재시작하세요.

## 11. 전체 워크플로 예제

### 예제 A — Template 모드: 간단한 문서 수정

> **목표**: `docs/API.md`에 새 엔드포인트 문서 추가

1. 사이드바 **+ 새 작업** → 제목 `API 문서 업데이트`, 대상 폴더 `C:\Code\my-project` → 생성.
2. Workbench 입력창 → 모드 `Template` 선택.
3. 입력: `docs/API.md 파일에 POST /users/bulk-create 엔드포인트 문서를 추가해줘. 요청 바디는 users 배열이고 응답은 created_count를 반환해.`
4. 전송 → 우측 패널 Plan 탭에서 생성된 파일 수정 계획 확인.
5. Approvals → 변경 diff 검토 → **승인** 클릭.
6. TaskRun 상태가 `done`으로 바뀌면 완료.

---

### 예제 B — Agent 모드: 코드 리팩토링

> **목표**: 인증 미들웨어를 클래스 기반에서 함수형으로 리팩토링

**전제**: Claude Code CLI 설치 확인 (상태바 `Claude ●` 초록색).

1. 사이드바 **+ 새 작업** → 제목 `Auth 미들웨어 리팩토링`, 대상 폴더 `C:\Code\backend` → 생성.
2. 입력창 → 모드 `Agent` 선택.
3. 입력:
   ```
   src/middleware/auth.ts의 AuthMiddleware 클래스를
   함수형 미들웨어로 리팩토링해줘.
   기존 테스트는 모두 통과해야 하고,
   타입 안전성을 유지해줘.
   ```
4. 전송 → `Agent 호출 중…` → Agent 탭에서 실시간 로그 확인.
5. 에이전트가 파일을 분석하고 변경 계획 수립 후 Approval 생성.
6. Plan 탭 Approvals에서 각 파일 변경 사항 검토:
   - `src/middleware/auth.ts` 변경 → 내용 확인 후 **승인**
   - `src/middleware/index.ts` 수정 → 확인 후 **승인**
7. Execute 후 TaskRun 상태 `done` 확인.

### 예제 C — Multi Worker 오케스트레이션

> **목표**: 프론트엔드와 백엔드를 동시에 수정 (장바구니 기능 추가)

1. **⚙ Agents** 버튼 → 오케스트레이션 **활성화**.
2. 실행 모드 **Multi Worker** 선택.
3. Worker 추가:
   - `백엔드 워커` / Coder / claude
   - `프론트엔드 워커` / Coder / claude
   - `코드 리뷰어` / Reviewer / auto
4. 기본 지시사항: `변경 전 테스트를 먼저 작성하세요.`
5. **저장**.
6. 사이드바에서 스레드 선택 → Agent 모드 → 요청 전송:
   ```
   장바구니 기능을 추가해줘.
   - 백엔드: POST /cart/add, DELETE /cart/remove, GET /cart 엔드포인트
   - 프론트엔드: CartIcon 컴포넌트와 CartPage 뷰
   - 각각 단위 테스트 포함
   ```
7. 에이전트들이 병렬로 작업하며 각각의 Approval을 생성합니다.
8. Plan 탭에서 백엔드/프론트엔드 변경사항을 별도로 검토 후 승인.

### 예제 D — 재지시(Redirect) 활용

> **목표**: 에이전트가 잘못된 방향으로 진행할 때 수정

1. Agent 모드로 `결제 모듈 테스트 작성` 요청 전송.
2. Plan 탭 Approvals에서 에이전트가 단위 테스트 대신 E2E 테스트를 제안했음을 발견.
3. Approval 항목의 **재지시** 입력란에 입력:
   ```
   E2E 테스트 말고 Jest 단위 테스트로 변경해줘.
   외부 의존성은 모두 mock 처리해줘.
   ```
4. **재지시** 버튼 클릭 → 에이전트가 새로운 방향으로 계획을 재수립합니다.

## 빠른 참조

| 동작 | 방법 |
|------|------|
| 새 스레드 | 사이드바 **+ 새 작업** |
| 스레드 삭제 | 목록 항목 오른쪽 **×** |
| 작업 전송 | Enter (줄바꿈: Shift+Enter) |
| 작업 삭제 | 채팅 버블 오른쪽 **×** |
| Agent 로그 보기 | Right Panel → Agent 탭 |
| 승인/거부 | Right Panel → Plan 탭 → Approvals |
| 오케스트레이션 설정 | 사이드바 **⚙ Agents** |
| 전역 설정 | 하단 상태바 **⚙** |
| 대상 폴더 변경 | 입력창 **변경** 버튼 |
