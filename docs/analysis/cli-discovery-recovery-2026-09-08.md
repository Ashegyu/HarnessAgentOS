# CLI 탐색 및 빈 계획 복구 — 2026-09-08

## 범위와 원인

- Windows 탐색기로 실행한 앱은 Codex 터미널의 버전별 PATH를 상속하지 않는다.
- 설치된 CLI는 `%LOCALAPPDATA%\OpenAI\Codex\bin\<build>\codex.exe`에 있었지만 기존 탐색기는 이 하위 경로를 확인하지 않았다.
- 입력창이 CLI 미감지 상태를 자동으로 `template` 모드에 연결하여 실행 세부 정보 없는 파일 승인을 생성했다.
- 상태 서비스가 호스트의 기본 계획(`harness:plan/…`)을 저장된 AI 답변으로 노출했다.

## 수정

1. 기존 override/npm/PATH 우선순위를 보존하면서 설치 루트 바로 아래 버전별 CLI 후보를 추가했다. 파일 수정 시각 순으로 탐색하며 불완전한 설치, 읽기 실패, 디렉터리 링크 및 경로 이탈 이름을 처리한다. 시스템 PATH를 변경하거나 프로젝트를 재귀 탐색하지 않는다.
2. 입력창은 전송 전에 CLI를 다시 확인하며, 실패하면 입력을 보존하고 작업 생성 전에 중단한다. 다시 확인 버튼과 한영 안내를 제공하며 정상 연결 시 항상 Agent 모드로 전송한다.
3. 기존 Template 계획은 원본 Artifact로 보존하되 최종 답변 후보에서 제외한다. 명시적 수동 Fallback/기존 IPC 호환은 유지한다.
4. 전체 검사에서 발견한 이전 복사 기능의 `APP_CLIPBOARD_WRITE_FAILED` 공유 오류 상수 누락을 보완했다.

기존 승인, blocked 작업 상태, 운영 DB, 실제 사용자 파일 및 필수 수동 승인 정책은 변경하지 않았다. 기존 빈 작업을 자동 재승인하거나 재실행하지 않는다.

## 검증

- 수정 전 CLI 탐색, 입력창 안내, Template 최종 답변 노출 테스트 실패를 재현한 뒤 같은 테스트의 통과를 확인했다.
- Electron E2E에서 연결 불가 및 IPC 실패 시 입력 보존/작업 미생성, 한영 전환, 재연결 후 빈 승인 없는 Agent 작업 생성이 통과했다.
- 전체 타입 검사 및 빌드 통과.
- Electron Node 모드의 전체 단위·통합 검사: 1,680개 중 1,678개 통과, 실패 0, 환경 의존 2개 제외. 설치된 Electron SQLite ABI를 유지했다.
- CLI 탐색 모듈 단위 커버리지: 줄 99.14%, 분기 84.21%, 함수 100%. 프로젝트 전체 커버리지 수치는 아니다.
- 전체 Electron E2E 최종 실행: 15/16 통과. 답변 복사 검사는 UI에 복사됨 표시 후 OS 클립보드 읽기가 빈 값인 경우로 실패했다. 해당 검사와 승인 검사를 묶은 별도 재검사는 5/5 통과했다. 따라서 전체 E2E가 안정적으로 모두 통과했다고 판단하지 않는다. 첫 전체 실행에는 별도의 테스트 환경 npm PATH 누락 및 앱 종료 오류도 있었으며, npm PATH는 해당 테스트 프로세스에서만 보완했다.
- `git diff --check` 통과. 별도 lint 스크립트는 없어 실행하지 않았다.
- `electron-builder --projectDir apps/desktop --win --dir`로 기존 `release/win-unpacked` 산출물을 갱신했다. 기존 Electron 배포본을 재사용했으며 네이티브 모듈 재빌드는 하지 않았다.
- 패키징된 main/preload/renderer HTML의 SHA-256이 현재 빌드와 일치했다.
- 실제 패키징 EXE를 별도 `.cache/packaged-cli-probe-XBdlBT/userData`와 일반 Windows PATH로 실행했다. `app.isPackaged=true`, CLI 0.153.4 탐색 성공, 빈 테스트 프로필의 스레드 0개를 확인하고 테스트 앱만 닫았다.

모델 호출은 가짜 모델로 격리했고 설치 CLI는 버전만 확인했다. 실제 계정 인증, 유료 모델 실행 및 HTML 보고서 작성 완료까지 검증한 것은 아니다. 기존 QA의 변경 0개 오판정은 이번 범위에서 수정하지 않았다.

## 사용자 재시도

갱신된 실행파일을 다시 열고 CLI 연결을 확인한 뒤 동일 요청을 새 작업으로 전송한다. HTML 파일 생성을 일반 에이전트 경로로 시도하려면 Pipeline은 일반 채팅, Harness는 없음으로 선택한다. 기존 실행파일 폴더 전체를 유지해야 하며 EXE만 단독으로 이동하지 않는다.
