총평

HarnessAgentOS는 “사용자 감독형 개발 워크벤치” 설계 의도에 맞게 잘 구축된 프로젝트입니다. Thread → TaskRun → Approval → Runner → QualityGate → Done 흐름이 코드·IPC·테스트에 일관되게 반영되어 있으며, packages/core가 storage를 import하지 않는 등 핵심 제약도 준수합니다.

“최적의 하네스” 관점: 감독·승인·증거 기반 완료라는 목표에는 매우 적합합니다. 다만 (1) 오케스트레이션이 기본 비활성, (2) in-repo 하네스 패키지가 예제 1개뿐, (3) Cursor/GAN/YAML 파이프라인 같은 외부 하네스 생태계와의 직접 연동이 없으며, (4) 자동 승인 경로의 proposedAction 검증 공백은 운영 시 혼란·실패를 유발할 수 있습니다.

기능 오류 가능성: 타입·계약 표면은 양호하나, 전역 자동 승인+실행 ON 시 템플릿 태스크에서 승인만 되고 실행이 실패하는 경로가 있습니다. 로컬 npm test는 better-sqlite3 ABI 불일치(또는 파일 잠금)로 대량 실패 — 코드 결함이라기보다 현재 머신의 네이티브 모듈 빌드 상태 문제로 판단됩니다.

1.1 TypeScript

모든 패키지(@harness/core, storage, runners, quality, orchestration, agent, evals, desktop 등)에서 tsc --noEmit 성공. 컴파일 수준의 구조적 오류는 발견되지 않았습니다.

1.2 테스트 (환경 이슈)

실패 원인 예시:

ERR_DLOPEN_FAILED: better_sqlite3.node was compiled against NODE_MODULE_VERSION 145.
This version of Node.js requires NODE_MODULE_VERSION 127.

Electron용(145)과 현재 Node 22(127) ABI가 섞여 있습니다. rebuild:node 재시도 시 EBUSY/EPERM으로 better_sqlite3.node 삭제 불가 — Electron dev 서버 또는 다른 프로세스가 파일을 점유 중일 가능성이 큽니다.

조치: Electron/데스크톱 앱 종료 → npm run rebuild:node → npm run test. CI에서는 별도 스크립트로 Node/Electron 각각 rebuild하는 패턴이 문서화되어 있습니다.

2.3 핵심 실행 경로

사용자 입력 → Thread → TaskRun → Step → Checkpoint
  → Approval (pending → approved) → Runner → Artifact
  → QualityGate → markDone → LearningTrace

Runner는 미승인 실행을 거부하고, 고위험 actionType은 차단합니다. markDone은 passed/warning QualityGate + (warning 시) known-risk 승인을 요구합니다.

8. Learner · Topology · Instincts — 동작·데이터 적재

결론: 완료된 TaskRun에 대해 learning trace는 markDone과 함께 쌓입니다 (reward, success, 선택 모델/스킬). Observations → evolution_candidates → instincts 경로도 품질 게이트·승인 이벤트로 데이터가 쌓입니다. 다만 trace의 cost/latency 필드는 비어 있는 경우가 많고, 실제 비용 UI는 agent_invocations를 봅니다. 취소·실패 run, topology만 피드백한 경우는 학습 데이터가 불완전할 수 있습니다.

8.5 LearnerAdvisor recommend — 데이터 사용

recommend()는 DB의 전체 learning_traces + capabilities를 읽어 in-memory로 재랭킹합니다. 프로젝트/기간 필터 없음 — TaskRun이 많아지면 비용·노이즈 증가 가능. 데이터는 쌓이지만 추천 품질은 이력 품질에 의존합니다.

8.6 알려진 갭

  • 비용 이중 모델: LearnerPanel trace의 cost vs CostPanel의 invocation 합 — 필드가 다름.
  • recordDecision: IPC·preload 있으나 React UI 미호출 → JSONL 감사 로그 거의 비어 있음.
  • markDone outcome: 항상 success: true 전달; warning gate는 reward(+0.25)로만 반영.
  • Learner vs Capability suggest: LearnerAdvisor가 suggester를 직접 import — CapabilityService와 profileId 전달 경로 불일치 가능.
