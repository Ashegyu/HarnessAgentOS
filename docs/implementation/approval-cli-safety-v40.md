# 승인·Windows CLI·단일 파일 삭제 변경 (v40)

이번 범위는 승인 버전 고정과 중복 실행 방지, Windows CLI 호출, 단일 파일 휴지통 이동, DB 이관 및 검증으로 한정한다. 모델·학습 확장이나 재귀 삭제, OS sandbox 구현은 포함하지 않는다.

## 사용자 동작

1. 파일 생성/수정/패치: 세부 내용 확인 → 승인 → 실행. 승인 뒤 세부 내용을 바꾸면 개별 확인과 재승인이 필요하다.
2. 명령 실행: 명령과 인수(JSON 배열)를 확인하고 호스트 접근 위험 확인 체크박스를 선택한 뒤 개별 승인한다. 빈 인수 칸은 기존 자유형 셸 명령이고, `[]`는 인수 없는 구조화 실행이다.
3. 파일 삭제: `file_delete` 제안의 세부 지정에서 경로를 저장 → 표시된 크기·수정 시각·SHA-256 확인 → 개별 확인 → 승인 → 실행. 휴지통 복원은 운영체제 휴지통을 이용한다. 폴더/와일드카드/.git/장치/ADS/정션/심볼릭 링크/하드 링크는 허용하지 않는다.
4. 실행 결과 확인 필요: 이미 일부 효과가 발생했을 수 있으므로 실제 파일·명령 결과를 먼저 검토한다. 기존 승인 ID를 재생하지 말고, 필요한 변경만 새 작업에서 제안·승인한다.

## Windows CLI 경로

- 설치된 실행 파일의 명시적 절대 경로 또는 앱이 상속한 PATH를 사용한다. npm/npx는 검증된 Node 실행 파일과 같은 설치의 npm-cli.js/npx-cli.js로 실행하며, 구조화된 인수를 cmd 문자열로 합치지 않는다.
- npm.cmd를 못 찾으면 PATH에서 발견한 Node 옆의 npm 설치 및 일반 Program Files/Node.js 위치를 확인한다. Node만 존재하고 npm이 없다면 설치/경로 안내를 표시한다. 특정 사용자 Codex 캐시 경로를 제품에 넣지 않는다.
- 실행 환경 설정이 필요한 경우 `HARNESS_NODE_PATH`, `HARNESS_NPM_CLI_PATH`, `HARNESS_NPX_CLI_PATH`에 검증된 절대 경로를 지정할 수 있다. 앱을 실행한 프로세스의 환경 변수이며 시스템 PATH를 자동 수정하지 않는다.
- 다른 임의 .cmd/.bat의 구조화 실행은 자동 shell 전환 없이 차단하고 실제 .exe 또는 Node + 스크립트 호출을 안내한다. 직접 작성한 자유형 셸 명령은 별도의 수동 승인 대상이다.
- UTF-8을 우선 해석하고, Windows 한국어 레거시 출력은 CP949(EUC-KR), BOM이 있는 UTF-16LE도 처리한다. 다른 지역의 레거시 인코딩까지 보장하지 않는다.

## DB 백업·이관·복구

- 실제 운영 DB는 이 작업에서 직접 변경하지 않는다. 새 빌드 실행 시 `applyMigrations`가 v40을 적용한다.
- 적용 전 앱을 완전히 종료하고 사용자 데이터 폴더의 `app.db`, 존재하는 `app.db-wal`, `app.db-shm`, `artifacts`를 **같은 시점의 별도 백업 폴더**에 함께 보관한다. 실행 중 DB 파일 하나만 복사하지 않는다.
- v40은 기존 작업/아티팩트/승인 기록을 유지한다. 실행 전의 예전 approved 기록은 검증 가능한 승인 버전이 없으므로 pending으로 바꾸고 수동 재승인을 요구한다. 실행 완료 기록은 유지한다.
- 첫 재시작 시 이전에 남아 있는 running 실행 선점은 uncertain으로 표시한다. 자동 재시도하지 않는다. DB 연결을 추가로 여는 것만으로 running 실행을 회수하지 않는다.
- 반복 이관은 무변경이다. 이전 앱으로 DB만 다운그레이드하거나 컬럼을 수동 제거하지 않는다. 되돌려야 하면 앱을 종료한 뒤 구버전 앱과 **대응하는 전체 사용자 데이터 백업**을 함께 복원한다. 이관 후 변경 기록은 백업으로 돌아가면 사라지므로 별도 보관이 필요하다.

## 보안·검증 경계

수동 승인은 OS sandbox가 아니다. 승인한 임의 CLI는 cwd 밖 파일과 네트워크에 접근할 수 있다. 파일 삭제는 경로/파일 정보를 실행 직전에 재검증하지만 Electron 휴지통 API는 파일 핸들 기반 원자적 비교·삭제를 제공하지 않는다. 악의적인 외부 프로세스가 검사와 OS 이동 사이에 경로를 바꾸는 경쟁까지 막는 OS 격리 보장으로 해석하지 않는다. 휴지통 실패 시 영구 삭제는 하지 않는다.

검증은 임시 targetDir/userData와 가짜 모델 응답을 사용한다. 파일 Runner, SQLite, Electron IPC/UI, 일반 CLI와 휴지통은 실제 구현을 실행한다. 유료 모델 추론, 외부 MCP/A2A, 배포, 패키지 설치 및 완전한 OS crash fault injection은 검증 범위 밖이다. 폐기된 실행 선점을 저장한 뒤 앱을 재시작하여 복구 동작을 검증한다.

회귀 테스트: `approval-safety.test.mjs`, `file-delete.test.mjs`, `windows-command.test.mjs`, `migrations.test.mjs`, `approval-acceptance.test.mjs`. 전체 검증 결과는 `docs/analysis/file-cli-approval-acceptance-2026-09-07.md`의 후속 검수에 기록한다.
