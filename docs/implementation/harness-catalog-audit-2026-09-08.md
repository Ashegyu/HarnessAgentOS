## 백업 및 오프라인 보정 도구

운영 적용 전 SQLite backup API로 WAL까지 포함한 일관된 복사본을 생성했다:

`C:\Users\USER\AppData\Roaming\@harness\desktop\backups\harness-config-frWgPB\before.db`

백업은 동일 사용자의 로컬 데이터 폴더에 있으며 외부로 전송하지 않았다. 복구가 필요하면 앱을 종료하고 백업과 운영 DB의 `harness_packages`, `harness_binding_sets` 차이를 검토한 뒤 대상 구성만 복원해야 한다. 이후 생성된 작업 기록을 잃을 수 있으므로 운영 DB 전체를 무조건 덮어쓰지 않는다. 이번 작업에서는 복원을 수행하지 않았다.

관련 도구:

- `scripts/maintenance/audit-harnesses.mjs <app.db>`: 읽기 전용 검사. 모델 CLI 환경·비밀정보는 출력하지 않는다.
- `scripts/maintenance/reconcile-harnesses.mjs <app.db> --dry-run`: 기본 모드. 읽기 전용으로 DB를 백업한 임시 복사본에서만 보정한다.
- `scripts/maintenance/reconcile-harnesses.mjs <app.db> --apply`: 앱 종료 후 명시적으로 사용. 백업 후 두 구성 테이블만 트랜잭션으로 변경한다. 다른 테이블 내용이 달라지거나 저장이 실패하면 롤백한다.

위 스크립트는 TypeScript 소스를 읽으므로 `--import tsx`와 현재 better-sqlite3 ABI에 맞는 런타임이 필요하다. 이 작업에서는 `ELECTRON_RUN_AS_NODE=1`인 Electron 런타임을 사용했다. 앱 시작 과정에서는 오프라인 보정 도구를 자동 실행하지 않는다.
