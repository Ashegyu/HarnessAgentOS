# Learn의 검사 결함 분류·검색과 동일 조건 재평가

## 판정

검사 수정 경험의 수집·검색 경로를 개선했고 제품 회귀 검사 156개, 타입 검사, 빌드를 통과했다. 그러나 **새 답안의 회귀 검사 품질 안정화와 이전 수정 대비 점수 상승은 확인하지 못했다.** 평가용 답안이나 새 실패를 학습 자료에 추가하지 않았다.

고정한 실행 소스는 `e3155df`다. 이전 유효 평가 소스는 `4e86659`이며, 이번 평가 이후 소스 변경은 이 검증 기록뿐이다. 모델은 `gpt-5.6-sol / medium`, 학습 3문제, 별도 평가 2문제, 조건별 2회, 총 8회 호출을 유지했다. 초기 코드·요청·정상 기준·숨겨진 검사·결함 변형·순서·예산·60+40 배점을 변경하지 않았다. 이전과 동일한 문제를 다시 사용한 개발 회귀 평가이며 새로운 맹검 평가가 아니다.

## 이전 60점의 원인과 변경

이전 LeasePool의 학습 후 두 번째 검사는 `DisposeAsync()` 반환 직후 lifetime token이 취소됐다고 단정했다. 계약은 admission의 즉시 차단을 요구하지만 취소 신호의 즉시 관측은 보장하지 않는다. 정상 기준은 `Task.Yield()` 이후 취소하므로 정상 동작도 거부했다. 기존 검색은 소유권 구현 경험만 선택하고, 이미 있는 검사 수정 경험은 주제어 겹침이 적다는 이유로 제외했다.

- 호스트가 회귀 실행의 기준/후보 종료 코드와 기준·후보·검사 내용 해시를 test_result 헤더에 기록한다. stdout에 있는 유사 문구는 분류 근거로 사용하지 않는다.
- 같은 계약·기준에서 실제 검사 내용 변경 후 정상 기준 실패가 재통과하면 `verification_repair`, 검사가 같고 후보 내용 변경 후 재통과하면 `implementation_repair`로 구분한다. 내용이 같은 파일 재저장 뒤 우연한 성공은 교훈으로 만들지 않는다. 기존 근거 없는 경험을 소급 분류하지 않는다.
- 승인된 검사 수정 경험은 같은 프로젝트의 검사 작성·수정·검토 요청에서 주제어가 달라도 찾는다. 일반 요청, 비활성 경험, 자기 작업, 다른 프로젝트 제한과 기존 문맥 슬롯을 보존한다.
- 원래 요청 범위를 유지하고, 호출 반환·신호 관측·비동기 완료를 구분하는 검토 정책을 실제 학습 사례에서 입증된 원인과 분리하여 표시한다.

별도의 `CloseSession` 제품 회귀 fixture에서 cleanup gate를 막아 취소가 지연되도록 했다. 잘못된 즉시 단정의 실제 C# 실패와 신호 대기·finally 정리를 적용한 검사의 실제 통과를 재현했다. 이 fixture는 평가 학습 DB에 넣지 않았다.

## 이번에 남은 60점

두 학습 후 출력 모두 취소 신호 대기를 생성했다. 그러나 두 번째 검사는 그보다 앞에서, 미리 취소된 요청이 반환하는 토큰의 `Generation`이 기존 live token과 같아야 한다고 단정했다. 계약은 취소된 Value·loader 미시작·현재 mapping 보존을 요구하며 그 반환 토큰의 Generation은 지정하지 않는다. 정상 기준은 이 경우 Generation 0을 반환한다.

평가 파일과 점수를 보존한 별도 진단 복사본에서 이 단정 하나만 제외하자 취소 신호·drain 검사를 포함한 나머지 전체가 정상 기준에서 통과했다. 이 실행은 재채점이나 학습이 아니다. 최초 점수는 60점으로 유지했다.

학습은 근거 있는 참고 경험의 전달을 개선하지만, 계약에 없는 기대값을 모델이 생성하지 않는다는 보장은 아니다. 제품의 등록된 정상 기준 실행 경로는 이런 검사를 거부할 수 있다. 이번 고정 평가의 answer-only·도구 금지 조건을 실행 허용으로 바꾸어 점수를 올리지는 않았다.
