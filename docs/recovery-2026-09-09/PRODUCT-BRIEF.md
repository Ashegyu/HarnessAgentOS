# 핵심 작업 흐름 복구안

작성: 2026-09-09 KST. 상태: 사용자의 설계·개발·검증 진행 요청에 따라 핵심 결함 수정과 로컬 검증을 수행했다. 전체 제품 또는 실제 모델 통합 검증 완료를 뜻하지 않는다. 결과와 검증 한계는 [VERIFICATION.md](./VERIFICATION.md)에 기록한다. DB 이관과 기존 기능 삭제는 수행하지 않았다.

## 누구의 어떤 문제를 해결하는가

대상은 로컬 프로젝트에서 분석·보고서 저장·코드 수정·검증을 요청하는 현재 사용자다. 사용자 보고에 따르면 작업 도중 실패·차단·미진행이 반복되고, 승인·작업 목적·하네스 설정을 직접 맞추어야 한다. 발생 빈도와 실패율은 아직 신뢰할 수 있는 운영 기록으로 계량하지 못했다.

사용자가 필요한 것은 설정 조합을 관리하는 기능이 아니라, 요청한 결과가 만들어지고 완료 여부와 중단 이유를 믿을 수 있는 작업 흐름이다.

## 확인한 사실과 아직 모르는 것

- 현재 checkout은 master이며 미커밋 변경 항목 203개다. 기존 변경은 보존한다.
- ConversationInput은 readOnly/noSearch 조건에서 사용자가 고른 하네스·파이프라인을 제출하지 않는다. ConversationStartService.prepare도 같은 조건이면 일반 에이전트 경로로 분기한다. 사용자의 선택과 실제 실행 방식이 달라질 수 있는 구조다.
- TaskProgressionService는 이미 main에서 진행을 조정한다. 따라서 새 조정 서비스 하나를 추가하는 것만으로 문제를 해결했다고 볼 수 없다. 기존 WorkerRunner·승인 실행·품질 판정과의 책임 및 전환 계약을 함께 정리해야 한다.
- 이전 검증에는 새 하네스의 구성·선택 검사와 일반 대화의 HTML 전달 검사가 포함되었지만, 새 HTML 하네스의 조사→작성→검토 전체를 실제 모델로 수행한 검증은 빠져 있었다.
- 이전 전체 E2E에는 답변 복사의 OS 클립보드 실패가 남아 있다.
- 사용자가 붙여준 첫 단계 결과만으로 현재 작업의 중단 위치나 원인을 확정하지 못했다. 재현되지 않은 모든 실패가 같은 원인이라고 가정하지 않는다.

## 방향 판단

결정: 전체 폐기 대신 **실패가 재현되는 핵심 실행 경로를 복구**한다. 기존 진행 조정기를 추가로 복제하거나 승인 보호를 제거하지 않는다. 아래 범위를 고정하고 실행 근거로 변경 필요성을 판단한다.

보존할 것:

- 저장된 프로젝트·대화·하네스·AgentProfile 및 원본 작업 파일.
- Electron/typed IPC, SQLite WAL과 실행 감사 기록.
- 검증된 승인 revision·단일 소비·경로 검증·취소 등 안전장치. 안전장치 전체가 완벽하다는 주장은 아니다.
- 현재 화면의 재사용 가능한 부분. 시각 디자인 전면 개편은 이번 범위가 아니다.

교체·정리할 것:

- 작업 분기, 단계 진행, 승인 후 재개, 결과 정리, 완료 판정을 하나의 명시적 진행 계약으로 통일한다. 새 분기나 우회 엔진을 기존 코드 옆에 추가하는 방식은 피한다.
- 모델은 결과와 실행 제안을 반환하고, 실행 엔진만 다음 단계와 사용자 작업의 최종 상태를 결정한다.
- 하네스는 같은 엔진이 읽는 실행 설정으로 취급한다. 일반 작업과 하네스 작업에 별도의 승인·완료 규칙을 두지 않는다.
- 사용자에게는 요청 입력, 진행 현황, 필요한 승인, 최종 결과를 우선 표시한다. 고급 기능은 보존하되 기본 작업을 시작하기 위한 필수 선택에서 제외한다.
- 명시적 하네스 선택과 읽기 전용 제약이 충돌하면 이유를 표시한다. 제약을 완화하거나 선택을 몰래 무시하지 않는다.
- 내부 JSON과 작업자 중간 출력은 상세 로그로 분리하고, 최종 결과는 사용자 요청의 산출물 기준으로 표시한다.

승인은 제거하지 않는다. 이미 유효하게 승인된 액션은 한 번만 실행하며 같은 승인을 재사용하지 않는다. shell·삭제·예산·권한 제한은 유지한다. 승인 대기, 입력 필요, 실행 실패, 결과 불확실을 서로 구분하고 각각 이유와 가능한 다음 동작을 표시한다.

## 이번 범위의 고정된 완료 기준

1. **설명 요청:** 불필요한 실행 승인·빌드 QA 없이 답변이 정상 표시되고 복사된다.
2. **HTML 저장 요청:** 실제 선택한 HTML 하네스의 조사→작성→검토가 모두 실행되고, 승인된 파일이 생성되며 실제 파일을 다시 확인한 뒤 결과와 경로를 표시한다.
3. **코드 수정 요청:** 격리된 프로젝트에서 변경 제안→승인→적용→관련 테스트→결과 안내가 이어진다. 사용자에게 별도의 “계속” 명령을 요구하지 않는다.
4. **중단·복구:** 승인 거절, CLI 실패, UI 새로고침, 앱 재시작 때 성공을 거짓 표시하거나 부수효과를 중복 실행하지 않는다. 결과가 불확실하면 자동 재실행하지 않고 확인이 필요한 근거를 보여준다.

평가 기준:

- 위 경로를 동일하게 패키징한 EXE와 격리된 DB/대상 폴더에서 검증한다.
- 결정적 통합·E2E에서는 정상 및 실패 경로의 예상 상태를 자동 단언한다. 필요한 정상 흐름을 여러 번 반복해 재개·단일 실행을 확인한다.
- mock 검증, 실제 로컬 CLI 검증, 실제 모델 검증 결과를 별도로 기록한다. 모델 호출은 사용자에게 승인된 범위·예산 안에서 수행하며, 인증·예산이 없으면 그 검증은 미완료로 남긴다.
- 원인 설명 없는 정지, 승인된 액션의 중복 실행, 파일이 없는데 저장 완료 표시, 중간 worker 결과를 전체 완료로 표시하는 사례는 허용하지 않는다.
- 테스트 개수나 빌드 성공만으로 제품 복구 완료를 선언하지 않는다.

## 비목표와 위험

- 이번 복구에 새 하네스, 원격 에이전트, 학습 기능, 자동 모델 추천, UI 전면 디자인 작업을 추가하지 않는다.
- 기존 고급 기능과 저장 데이터를 삭제하거나 초기화하지 않는다. 기본 흐름에서 분리하는 방안만 제안한다.
- 이미 진행·실행된 사용자 작업을 새 엔진으로 자동 재실행하지 않는다.
- 기존 203개 변경 항목과 겹치는 수정은 작은 단위로 수행하고, 저장 데이터의 형식 변경이 필요해지면 별도 백업·호환성·복구 검토가 필요하다.
- 아직 원인이 확정되지 않은 모든 결함의 해결을 이 문서만으로 약속하지 않는다. 범위 밖 결함은 기록하고 핵심 복구에 자동으로 끼워 넣지 않는다.

이 네 가지 사용자 흐름의 완료 근거가 확보되면 이번 복구를 끝낸다. 추가 기능은 별도 요청이 있을 때만 다룬다.

## 구현 결과 요약

- 하네스 선택과 작업 계약의 충돌은 조용히 일반 채팅으로 바꾸지 않고 입력을 유지한 채 알린다. 화면과 main은 같은 순수 정책 함수를 사용한다.
- JSON 문자열 안의 Markdown 코드 펜스를 응답 끝으로 오인하던 실행/화면 파서를 공유 추출기로 수정했다.
- 후속 worker의 검증 불가능한 USD 예산은 첫 worker 실행 전 확인한다. 설정 저장은 가능하게 유지하고 준비 상태에는 경고를 표시한다. 저장된 예산을 자동 제거하지 않는다.
- 수동 위험 확인 전에는 승인 후 실행 버튼을 활성화하지 않는다. 승인 revision과 단일 소비 계약은 유지한다.
- 복사는 OS 읽기 결과가 원문과 같은 경우만 성공으로 표시한다. 일시적 실패는 최대 3회, 총 대기 100ms 범위에서 재시도한다.
- 실제 선택한 HTML/코드 하네스, CLI 실행, 실패/재시작과 승인 보호를 격리된 프로젝트에서 검증했다. 모델 응답은 결정적 대체 어댑터를 사용했다. 실제 모델을 통한 전체 네 가지 흐름은 미검증이므로 이 문서의 제품 복구 완료 조건 전체를 충족했다고 주장하지 않는다.
